# ADR-0012: 학습 target 구두점 정규화 정책

## 상태

채택 (2026-05-30) · Tier A·B 구현·검증 완료 (2026-05-31)

## 맥락

학습된 어댑터에 대한 모델 피드백 4건:

1. 문장부호가 띄어쓰기되어 출력됨 (`word .`).
2. 일부 부호(쉼표·느낌표)가 생략되거나 온점으로 바뀜.
3. 문법적 오류가 고쳐지지 않음.
4. 접속사·부사 오용이 고쳐지지 않는 경우가 있음.

`data/pairs/SBCSAE/` 전수 감사 결과 (n=3,514, target = `spoken_text`):

| 지표 | spoken_text (target) | formal_text (입력) |
|---|---|---|
| 부호 앞 공백 `' .'` | **23,698회 / pair의 100%** | 82회 / 2% |
| 쉼표 총개수 | **24개** (쉼표 없는 pair 99.3%) | 16,420개 |
| 종결 `. : ? : !` | 22,738 : 1,674 : **0** | 16,184 : 1,664 : 0 |
| 중복 종결 `'. .'`/`'..'` | 490회 / 12.9% | — |

학습 방향은 `formal_text(정문) → spoken_text(원어민 전사)` 이다 (`training/formatters.py`).
즉 **모델의 정답이 SBCSAE CHAT 전사본 그 자체**이고, 위 결함은 모델 능력 한계가
아니라 우리 target 데이터의 전사 표기 잔여물이다. CHAT 전사는 (a) 종결자를 `word .`처럼
공백+부호로 찍고, (b) 거의 모든 종결을 `.`로 표기하며 쉼표는 운율 표시로만 드물게 쓰고
`!`는 쓰지 않는다. 모델은 이를 충실히 학습했다.

## 결정

피드백을 세 갈래로 분리해 처리한다.

### 1. Tier A — 기계적 구두점 정규화 (즉시)

전사 신호에 이미 존재하는 부호의 **표기만** 정규화한다. 결정론적·regex.

- 부호 앞 공백 제거: `word .` → `word.` (`. , ? ! ; :`)
- 연속 온점 정리: `..` / `....` → `.`, 단 생략부호 `...`는 보존

이 정규화는 **코퍼스 무관 텍스트 후처리**이므로 CHAT cleaner에 묶지 않고
공유 모듈 `scripttuner/preprocessing/text_normalize.py:normalize_punctuation`에 둔다.
적용 지점은 **두 곳**이다:

- ② Cleaner (`chat/cleaner.py`) 최종 단계 — 학습 target을 깨끗하게.
- 추론 후처리 (`training/generate.py:_postprocess`) — `<pause:*>` 토큰 strip 직후.
  target이 pause 토큰을 유지하므로(ADR-0008), 추론 시 토큰을 제거하면 그 자리에서
  `' .'`가 다시 생긴다. 따라서 학습·추론 양쪽에서 같은 함수를 적용해야 한다.

→ 피드백 1번 완전 해결. 2번의 "온점화"(`. .`)는 완화.

### 2. Tier B — 재구두점 (쉼표·`?` 복원) (구현안 1 — 구현·검증 완료)

> 용어: **Tier A/B**는 *무엇을* 고치냐(범위), **구현안 1/2**는 Tier B를 *어떻게*
> 구현하냐다. 혼동을 피하려고 이전의 "방식 A/B"를 "구현안 1/2"로 개명한다.
> - 구현안 1 = 자유생성 + 사후 토큰검증 (채택)
> - 구현안 2 = 토큰 정렬 강제 (미채택: 긴 입력에서 LLM 슬롯 라벨링이 자주 깨짐)

쉼표·`?`는 전사 신호에 **없으므로** 정제가 아니라 *생성*이 필요하다. **구현안 1
(자유생성 + 사후 토큰검증)**: 제약 LLM에 "구두점·대소문자만 삽입, 단어 불변"을
지시 → 출력의 단어열이 입력과 동일한지 검증(불변식). 깨지면 그 pair는 **Tier A로
폴백**(데이터 손실 0). 재구두점은 **target(`spoken_text`)에만** 적용하고 ④ LLM
입력에는 적용하지 않는다(formal 생성 품질과 무관).

**PoC 결과** (59쌍 성공, 토큰 길이 3분위 균등, `openai/gpt-oss-120b:free`):
- 단어보존 불변식: 정규화 비교 기준 실제 단어변경 ~8/58 ≈ **14%** → 전부 폴백 처리.
  (strict 검증의 표기차 — `'em`↔`em`, `do-`→`do`, `well-behaved`→`well behaved` —
  는 단어 보존으로 간주.)
- 품질: 필러·false-start·축약 보존 양호, 쉼표가 절 경계에 자연스럽게 삽입, 물음표 복원.
- **`!`는 채택 안 함**: excl 변이도 59쌍 중 `!` 1개만 생성. 근거 없는 감정 주입 위험만
  있어 쉼표·`?`로 한정(`no_excl`).

**pause 토큰 재삽입**: 불변식 통과분만 Tier B를 적용하므로 입출력 단어가 1:1
대응한다. 원본 `<pause:*>`가 "N번째 단어 뒤"인지를 기록해 재구두점 출력의 같은
단어 경계에 결정론적으로 재삽입한다(ADR-0003 학습신호 보존).

**LLM 라우팅**: OpenRouter 1차(무료 관대), 거부/에러분만 차후 Groq 2차 패스로 보충.
배치 처리는 에러 pair를 기록하고 계속 진행한다(전체 중단 금지).

**프롬프트 보강(본 구현 시)**: PoC 위반 분석상 구조 문제는 없고 프롬프트는 대체로
견고하나, 본 구현 전 2줄 추가한다 — (a) 출력에 줄바꿈을 넣지 말 것(PoC 출력에 가끔
`\n` 삽입), (b) 입력의 모르는 기호·마커는 그대로 둘 것(단어 누락 방어선). 위반의
주원인은 프롬프트가 아니라 위 전사 마커 잔존(이번에 cleaner에서 해소)과 검증기 과민
(표기차)이었다.

검증 결과(부호 before/after·구어성 회귀)는 [`report/metrics_summary.md`](../../report/metrics_summary.md).

### 3. 문법 교정 (피드백 3·4) — 스코프 밖

본 모델은 grammar corrector가 아니라 구어성/스타일 transfer다. 학습쌍이
`정문 → 정문`이라 모델은 "이미 올바른 문장의 스타일 변환"만 학습했고 L2 오류를
본 적이 없다. 따라서 오류 통과는 능력 한계가 아니라 **설계상 전제**다.
**"입력은 문법적으로 정상"을 전제로 명시**하고, L2 입력 강건성(입력 측 L2 오류를
포함한 학습쌍 확보)은 보류 항목으로 추적한다.

## 결과

- **장점**: 피드백 1번이 학습·추론 양쪽에서 결정론적으로 해결. 정규화 로직 단일 출처.
- **비용**: Tier A를 cleaner에 넣으면 ④ 캐시 키(`make_cache_key(prompt_version, model, pause_strip(spoken))`, `pairs.py`)가 바뀌어 재호출이 발생한다. 현 생성 모델이 `openai/gpt-oss-120b:free`라 금전 비용은 ~0 (시간·레이트리밋만).
- **한계**: Tier A만으로는 쉼표 과소사용(피드백 2번 일부)이 남는다 → Tier B에서 해결.
- **검증**: Tier B 적용 모델(`-repunct`)이 동일 config baseline(`-es`) 대비 피드백 1·2를
  해소(쉼표 복원·`' .'` 제거)하고 구어성(filler/pause/length) 회귀 없음을 확인 — 상세
  [`report/metrics_summary.md`](../../report/metrics_summary.md).
- **후속**: 기존 `pairs.py:_normalize_typography`(스마트 따옴표→ASCII)도 동일 공유 모듈로 통합 가능(선택, 별도 정리).
